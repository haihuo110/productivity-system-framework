## 1. Purpose
把已确认的岗位能力标准编排为可实施、可评价、可迭代的课程蓝图，确保教学目标、内容、实践、评价和资源与岗位证据一致。

## 2. Inputs
- 已发布或明确标注状态的 `skill-matrix-v1`。
- 学制、学时、班级规模、师资、场地、设备、预算与安全约束。
- 学习者先备知识、无障碍与分层教学要求。
- 评价政策、行业认证与企业验收标准。

## 3. Outputs
输出 `curriculum-blueprint-v1.json`：课程元数据、模块序列、学习成果、教学活动、评价蓝图、资源配置、风险和完整链条 `JOB -> COMP -> MOD -> SCN -> WO`。任何学习成果都必须能回溯至少一个 `COMP-*`，任何核心 `COMP-*` 都必须有教学与评价覆盖。

## 4. Operating procedure
1. 校验岗位矩阵版本、状态和能力链条。
2. 建立能力依赖图，识别先修、并行和汇聚模块。
3. 将能力分配到 `MOD-*`，定义可测量学习成果和掌握阈值。
4. 将模块拆为 `SCN-*` 场景，匹配真实工作条件、设备和安全控制。
5. 设计形成性/总结性评价，规定证据、评分量表、重做规则。
6. 估算学时、师生比、设备并发、材料消耗与风险控制。
7. 输出版本化蓝图，执行覆盖率、依赖无环、资源可用性和专家评审。

## 5. Design rules
- 以工作证据倒推教学活动，不以教材章节倒推能力。
- 关键安全与质量能力必须有独立学习成果和门槛评价。
- 每个模块至少一个场景；每个核心场景至少一个可执行工单。
- 学习成果使用“在条件下完成可观察行为并达到阈值”的格式。
- 允许差异化路径，但不得绕过必需先修和安全门槛。

## 6. Verification
自动检查：schema、ID 唯一、链条完整、能力覆盖率、先修无环、总学时平衡、评价证据存在、资源容量不超限。专家检查：行业真实性、教学可行性、评价公平性、风险控制与就业相关性。未通过项写入 `open_issues` 并阻止 `verified` 发布。

## 7. Failure handling
能力无法落入模块时返回 `unmapped_competencies`；资源不足时给出容量冲突和可行替代，不静默删减核心成果；评价无法测量时返回 `assessment_gap`。

## 8. ID tracking chain
`JOB-*` 来源岗位 → `COMP-*` 目标能力 → `MOD-*` 教学模块 → `SCN-*` 教学/实训场景 → `WO-*` 可执行工单。模块重组不得改变上游 ID；被替换对象需保留 `supersedes`。
