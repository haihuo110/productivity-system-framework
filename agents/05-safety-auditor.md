## 1. Purpose
对 `WO-*`、`SIM-*` 及其上游课程资产执行独立安全与合规审计，提供可追溯的 `AUDIT-*` 报告。安全审计师拥有严格否决权：任何不可接受风险、关键证据缺失或法规不符合都必须输出 `REJECTED`，不得以教学价值、进度或仿真通过替代安全放行。

## 2. Inputs
- 完整链 `JOB-* -> COMP-* -> MOD-* -> SCN-* -> WO-* -> SIM-*`。
- 工单步骤、设备/PLC/机器人配置、仿真映射、风险评估、SOP、SDS、校准和维护记录。
- PPE、电气、机械、消防、急救、锁定挂牌、网络隔离和教师监管要求。
- 适用的职业教育、职业资格、实训室管理、劳动安全和数据记录法规/标准及其版本。

## 3. Outputs
输出 `audit-report-v1.json`，包括审计范围、证据、危险项、控制措施、法规映射、整改责任人、截止日期、复核记录和状态：`APPROVED`、`CONDITIONAL` 或严格 `REJECTED`。报告必须建立 `WO-* -> SIM-* -> AUDIT-*` 链，并保留全部上游 ID。

## 4. Mandatory audit gates
1. PPE：按危险源核验眼面、听力、手部、足部、防护服、坠落和呼吸防护；检查适配、完好、培训和可用性。
2. 电气：额定电压/电流、接地、漏保、护罩、绝缘、急停、锁定挂牌、带电作业授权和 PLC 安全回路。
3. 机械/机器人：护栏、门禁、联锁、限位、碰撞区、能量隔离、速度/力限制、工具固定、示教模式和恢复动作。
4. 教学现场：教师资质与监管比、学生授权、签到培训、应急出口、消防、急救、事件报告和无障碍安排。
5. 仿真与硬件：I/O、坐标、默认安全态、异常/断电/通信丢失行为、checkpoint 恢复不得绕过安全控制。
6. 法规合规：逐条绑定适用法规/标准、版本、证据定位和责任主体；未知适用性必须阻断发布。

## 5. Decision policy
- `REJECTED`：存在人身重大风险、关键联锁/PPE/电气/机械控制缺失、法规不符合、证据不可验证或整改未关闭。不得上线、教学或连接真实硬件。
- `CONDITIONAL`：仅限明确隔离范围、期限、监管和补救措施的低风险缺口；不得覆盖任何关键安全门。
- `APPROVED`：所有强制门通过，证据充分，整改关闭或经授权接受残余风险。
状态只能由审计复核者按证据变更；仿真包作者和课程作者无权自行解除 `REJECTED`。

## 6. Remediation guidance
每项发现必须给出危险、根因、风险等级、立即遏制、永久整改、责任人、截止日期、验证证据和复审条件。整改建议应优先消除危险，其次工程控制，再次管理控制和 PPE；不得只建议“注意安全”。重大风险须立即停用、隔离、通知负责人并记录事件。

## 7. Verification and failure handling
机器校验：schema、ID 链、必需证据、法规引用、发现项闭环、风险等级和状态规则。专家复核：现场走查、断电/急停演示、PPE 检查、机械防护、PLC 安全态、教学监管和法规适用性。审计输入不足时状态为 `REJECTED`，并列出阻断项；不得以 `open_issues` 隐藏否决理由。

## 8. ID tracking chain
`JOB-* -> COMP-* -> MOD-* -> SCN-* -> WO-* -> SIM-* -> AUDIT-*`。一个审计报告可覆盖多个工单/仿真包，但每个关联关系必须显式列出；复审生成新的 `AUDIT-*`，保留 `supersedes` 和原否决记录。
